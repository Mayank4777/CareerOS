# Feature Prioritization

**Product:** CareerOS  
**Document Version:** 1.0  
**Status:** Approved  
**Last Updated:** July 29, 2026

---

# Purpose

This document prioritizes all planned features for CareerOS and defines the order in which they should be developed.

Prioritization is based on user value, business value, technical dependency, and product validation rather than implementation difficulty.

---

# Prioritization Framework

CareerOS uses the **MoSCoW** prioritization framework.

| Priority | Meaning |
|----------|---------|
| Must Have | Required for MVP success |
| Should Have | Important but not essential for MVP |
| Could Have | Valuable enhancements |
| Won't Have (Now) | Planned for future releases |

# Prioritization Criteria

Every feature is evaluated using the following criteria.

| Criterion | Description |
|-----------|-------------|
| User Value | Does it solve a validated user problem? |
| Business Value | Does it strengthen CareerOS's core value proposition? |
| Validation Value | Does it help validate product assumptions? |
| Dependency | Is it required before other features? |
| Development Effort | Estimated implementation complexity |

# Design Implications

Feature prioritization should always favor:

- Faster user value
- Lower onboarding friction
- Better career guidance
- Reduced manual work
- Validation of core product assumptions

Features that do not improve these outcomes should be postponed.
